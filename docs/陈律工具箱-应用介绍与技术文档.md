## 一、应用介绍

### 1.1 定位

**陈律工具箱**是一款面向法律从业者（律师、法务、基层法律工作者）的 Android 离线效率工具。它把法律人日常高频的**文书排版、PDF 处理、公众号排版**四件事，集成到一个 App 里，用手机就能完成，不依赖电脑。

核心理念：**一个领域工具箱，解决一类人的高频痛点**。

### 1.2 四大功能模块

| Tab | 名称 | 功能 | 解决的痛点 |
|-----|------|------|-----------|
| MD | Markdown 编辑 | Markdown 编写 + 格式工具栏 + 草稿自动保存 + 一键转公文 | 手机上写 Markdown 缺快捷格式按钮，容易丢内容 |
| word | 公文排版 | Markdown/Word 转公文 + 就地编辑 + 撤销重做 + 导出 .docx/.pdf | 公文格式繁琐（字体/字号/行距/缩进/页边距），手动排版耗时 |
| PDF | PDF 工具 | PDF 加页码 + PDF 盖章（拖拽定位、旋转、层级开关） | 手机端无免费工具能给 PDF 加页码/盖电子章 |
| 公众号 | 公众号排版 | Markdown 转公众号排版 + 5 套主题 + 一键复制粘贴 | 公众号编辑器粘贴后排版错乱（行距宽、表格断裂） |

### 1.3 核心特色

- **纯离线**：所有功能本地执行，不上传任何文件，保护当事人隐私
- **公文规范**：内置国标通用 / 法院诉讼 / 行政机关三套公文排版预设，参照 GB/T 9704
- **Word/PDF 双格式对齐**：同一份公文模型，导出 Word 和 PDF 版式逐项一致
- **run 级编辑**：打开 Word 文档后可按字段（run）编辑，保留下划线、变长跟随
- **公众号粘贴零错乱**：100% 内联 HTML + 表格固定布局，粘贴到公众号助手不丢样式
- **WebView 原生复制**：复制按钮与输入法全选-复制完全同源，粘贴效果一致
- **撤销/重做**：公文编辑全程支持 40 步历史栈，杜绝误改丢失
- **草稿自动保存**：Markdown 和公文草稿防抖 1.5s 自动持久化，意外退出不丢

### 1.4 适用人群

- 律师、基层法律服务工作者：手机起草诉状、合同、法律意见书
- 企业法务：快速排版合规文件、给 PDF 盖电子章
- 法律自媒体：Markdown 写普法文章，一键排版发公众号

### 2.3 架构设计

#### 整体架构

采用**单 Activity + Compose Navigation** 架构（非 Jetpack Navigation 组件，而是枚举路由）：

```
MainActivity (入口)
  └─ AppScreen (状态管理 + 路由)
       ├─ 顶部 TopAppBar（标题 + 当前模式标签）
       ├─ 内容区 when(mode)
       │    ├─ DOC  → DocumentScreen
       │    ├─ GOV  → GovDocScreen
       │    ├─ PDF  → PdfScreen
       │    └─ WECHAT → WeChatScreen
       └─ 底部 NavigationBar（4 Tab）
```

**路由设计**：用 `DocMode` 枚举 + `remember` 状态管理，不引入 ViewModel/Navigation 组件，保持轻量。`GovDoc` 模型在 MD 和 word 两 Tab 间共享——MD 页生成公文后自动跳转 word 页，无缝对接。

#### 公文模型（核心数据结构）

`GovDoc` 是整个 App 的核心数据模型，与输出格式解耦：

```
GovDoc (可序列化)
├─ blocks: List<Block>        # 内容块（标题/段落/表格/落款）
│   └─ Block
│       ├─ type               # TITLE / PARA / TABLE / SIGNATURE
│       ├─ runs: List<Run>    # 文本片段（带样式：粗体/斜体/下划线）
│       └─ rows: List<Row>    # 表格行（仅 TABLE 类型）
├─ page: PageSetup            # 纸张/页边距/页码
├─ title, fonts, sizes...     # 排版规范参数
└─ pageNumber: Boolean        # 是否添加页码
```

同一份模型可输出三种形态：
- **Word**：`DocxWriter` 手写 OOXML（zip + XML），精确控制公文每处排版
- **PDF**：`PdfExporter` 用 Android 原生 `PdfDocument` 矢量渲染
- **屏幕预览**：`GovDocScreen` 用 Compose `Canvas` / `Text` 渲染

#### 撤销/重做系统

```kotlin
// 纯内存快照栈，GovDoc 不可变（copy 浅拷贝，ByteArray 共享）
var undoStack by remember { mutableStateOf<List<GovDoc?>>(emptyList()) }
var redoStack by remember { mutableStateOf<List<GovDoc?>>(emptyList()) }
val MAX_HISTORY = 40

fun commitDoc(next: GovDoc?) {
    undoStack = (undoStack + govDoc).takeLast(MAX_HISTORY)
    redoStack = emptyList()   // 新操作清空重做栈
    govDoc = next
}
```

不依赖持久化，离线零依赖，退出后清空。

### 2.4 关键技术实现

#### 2.4.1 手写 OOXML 生成 Word（无 POI 依赖）

`.docx` 本质是 zip 包 + XML 部件。`DocxWriter` 不引入 POI 重型库，直接手写 XML：

```kotlin
// 单位换算
fun ptToHalfPt(pt: Double): Int = (pt * 2).roundToInt()  // OOXML 字号
fun ptToTwips(pt: Double): Int  = (pt * 20).roundToInt()  // 行距/缩进
fun cmToTwips(cm: Double): Int  = (cm * 566.929).roundToInt()  // 页边距

// 生成 docx = zip(document.xml + styles.xml + ...)
ZipOutputStream(out).use { zip ->
    zip.putNextEntry(ZipEntry("word/document.xml"))
    zip.write(documentXml.toByteArray())  // 手写 OOXML
    // ...
}
```

**优势**：体积小、完全掌控公文排版细节（字体/字号/行距/缩进/页边距/页码域）、不依赖 6MB+ 的 POI。

#### 2.4.2 公文排版规范（GB/T 9704）

`MdToGongwen.kt` 内置三套预设：

| 规范 | 标题字体 | 正文字体 | 字号 | 行距 | 页边距 |
|------|---------|---------|------|------|--------|
| 国标通用 | 方正小标宋简体 22pt | 仿宋_GB2312 16pt | 三号 | 28pt 固定 | 上3.7/下3.5/左2.8/右2.6cm |
| 法院诉讼 | 方正小标宋简体 22pt | 仿宋_GB2312 14pt | 四号 | 25磅 | 同上 |
| 行政机关 | 方正小标宋简体 22pt | 仿宋_GB2312 16pt | 三号 | 28pt 固定 | 同上 |

Markdown → 公文的映射规则：
- `#` → 一级标题（居中、二号、空行）
- `##` → 二级标题（黑体、三号、首行缩进2字）
- `###` → 三级标题（楷体、三号）
- `####` → 四级标题（仿宋、三号）
- 正文 → 仿宋三号、首行缩进32pt、行距28pt
- `ll ` 前缀 → 顶格不缩进
- `---` 之后 → 落款区（右对齐）
- 表格 → 三线/全框线、单元格不缩进
- 自动识别主送机关（「尊敬的审判员：」顶格）

#### 2.4.3 PDF 导出（与 Word 版式对齐）

`PdfExporter` 用 Android 原生 `PdfDocument` 矢量渲染，严格复用 `GovDoc` 模型：

- 页面尺寸/页边距读取 `doc.page`（不硬编码）
- 两端对齐按「排版单元」分配间距（连续 ASCII 字母数字视为整体，不拆开 `GB/T` `2025`）
- 行首/行尾禁则（标点不出现在行首/行尾）
- 主标题避免孤行（页尾放不下提前换页）
- 表格行高自适应、跨页表头重复

#### 2.4.4 PDF 盖章

印章定位用**真实 PDF pt 坐标**（非屏幕像素），修复了 `density ≠ 1` 时印章被推出页面外的问题：

- 拖拽定位：`detectTransformGestures` 捕获偏移量
- 坐标换算：`PdfCoordinateUtils` 屏幕 px ↔ PDF pt
- 旋转：印章可旋转任意角度
- 层级开关：印章可置于内容上层或下层
- 图像型 PDF 支持：对扫描件（图片型 PDF）也能盖章

#### 2.4.5 公众号排版引擎（两路分离）

这是技术含量最高的模块。核心设计：**预览和粘贴走两条不同的 HTML 生成路径**。

**为什么必须分离？**

微信公众号编辑器（手机助手 / 网页后台）在粘贴时会**彻底丢弃 `<html><head>` 区块**，包括 `<style>` 标签和所有 class 选择器，只保留「标签裸结构 + 行内 style」。

| 路径 | 函数 | 输出 | 用途 |
|------|------|------|------|
| 预览 | `convertForPreview()` | 完整 HTML 文档（含 `<head><style>`） | WebView 预览渲染 |
| 粘贴 | `convertForCopy()` | 100% 内联、零 class 的 `<section>` 片段 | 剪贴板 |

**`convertForCopy` 处理流程（6 步）：**

1. commonmark + 扩展解析 Markdown 为 HTML
2. Jsoup 清洗：移除 class/id/style/script，仅留语义
3. CSS 逐元素内联（标签选择器匹配，不依赖 class）
4. **硬兜底**：body 级 `line-height`/`font-size`/`font-family`/`color` 直接落到每个文本元素（含 `strong`/`em`/`span`/`a` 等行内元素）
5. **表格硬兜底**：`table-layout: fixed` + `width: 100%` + 首行逐列均分 + `border-collapse` + HTML 属性 `border/cellspacing/cellpadding`
6. 压缩空标签，用 `<section>` 包裹输出

**表格不断裂的关键：**

公众号粘贴表格散架的根因是缺 `table-layout: fixed` 和逐列宽度。解决方案：

```css
table  { table-layout: fixed; width: 100%; border-collapse: collapse; box-sizing: border-box; }
th, td { border: 1px solid #dfdfdf; padding: 8px 10px; word-break: break-word; }
/* 首行逐列均分 width: 33% (3列) */
```

+ HTML 属性 `border="1" cellspacing="0" cellpadding="6"`（公众号保留 HTML 属性）

**复制按钮同源设计：**

复制按钮不走手搓内联片段，而是调用 WebView 原生 `selectAll + execCommand('copy')`，与输入法全选-复制完全同源，粘贴效果 100% 一致。编辑态点复制时，先切到预览、等 `onPageFinished` 加载完成后再执行复制。

### 2.5 UI 设计

#### 主题

法律红（`#B03A2E`）为主色，米白（`#FDFBF8`）为背景，体现法律庄重感：

```kotlin
lightColorScheme(
    primary = Color(0xFFB03A2E),           // 法律红
```

#### 布局原则

- **底部操作栏固定一行**：所有设置和结果操作放对话框，保证任意屏幕尺寸功能可见
- **编辑/预览互斥**：用子 Tab 切换，不同时挂载（避免 WebView surface 叠层）
- **紧凑化**：按钮 38-46dp 高度、图标 34dp、间距 6dp，手机单手可操作

### 2.6 数据持久化

| 数据 | 存储方式 | 说明 |
|------|---------|------|
| Markdown 草稿 | SharedPreferences (JSON) | 防抖 1.5s 自动保存，进入恢复 |
| 公文草稿 | SharedPreferences (kotlinx.serialization) | 同上 |
| 公文设置 | SharedPreferences | 纸张/页边距/字号等 |
| 主题 CSS | SharedPreferences | 自定义 CSS 可保存/恢复 |

不引入 Room/SQLite——个人工具不需要关系型数据库，轻量优先。

## 四、已知限制与未来方向

### 当前限制

- 仅支持 Android，无 iOS 版本
- Word 读取依赖 POI（体积较大），生成走手写 OOXML
- 公众号排版在手机端「公众号助手」App 与电脑网页后台效果可能略有差异
- 撤销/重做为内存栈，退出 App 后清空

### 可扩展方向

- 云同步：草稿/设置跨设备同步
- 模板库：预设常用法律文书模板（诉状/合同/意见书）
- 批量处理：PDF 批量加页码/盖章
- iOS 版本：React Native / Flutter 跨平台重写
